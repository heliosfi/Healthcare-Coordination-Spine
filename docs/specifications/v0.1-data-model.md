# Healthcare Coordination Spine — v0.1 Data Model

**Documentation baseline frozen under N.B.C. authority on 2026-10-03.** This readable specification carries the [uploaded v0.1 model](../../archive/source-artifacts/v0.1-data-model.html) plus the subsequently authorized closure completion. The uploaded HTML remains unchanged. Examples are synthetic; the source's “Core JSON schema” is an illustrative JSON object, not a formal JSON Schema validator.

## 1. Design principles

- Access does not create authority. Reading a record confers no write privileges.
- The Spine never overwrites source data; it indexes and references.
- Every consequential state is source-attributed: status, source, and timestamp are inseparable.
- Conflict is a first-class state and causes `HOLD`, not silent overwrite or last-write-wins.
- **Responsibility moves. Authority does not.** Responsibility moving from payer to pharmacy or pharmacy to patient does not transfer source-domain write privileges. The prescriber's clinical authority persists through those handoffs.

## 3a. Happy path and responsibility handoffs

| Verified state | Source domain | Responsible actor | Bounded next action / patient action |
|---|---|---|---|
| `APPROVED` | Payer | PHARMACY | Process fill; patient action None |
| `PHARMACY_PROCESSING` | Pharmacy | PHARMACY | Complete pharmacy processing; patient action None |
| `READY` | Pharmacy | PATIENT | Pick up prescription |
| `DISPENSED` | Pharmacy | PATIENT | Confirm receipt if required by episode |
| `PATIENT_RECEIPT_KNOWN` | Patient | PRESCRIBER | Workflow-defined follow-up; confidence remains patient-reported |
| `FOLLOW_UP` | Prescriber / bounded workflow evidence | PRESCRIBER | Complete required coordination follow-up |
| `CLOSED` | Spine closure attestation | null | No outstanding required action |

The source's example “Schedule adherence check” is a coordination task; it does not establish adherence. Follow-up obligations come from an explicit workflow/care-plan context, not an inferred clinical conclusion.

## 4. Conflict object

The original example is preserved here:

```json
{
  "conflict": {
    "detected_at": "2026-10-03T09:00:00-04:00",
    "sources": [
      {"system": "Surescripts", "value": "APPROVED"},
      {"system": "Health Plan X", "value": "NEEDS_INFORMATION"}
    ],
    "resolution_state": "HOLD",
    "responsible_actor": "SPINE",
    "next_required_action": "Reconcile with payer source of truth",
    "promotion_blocked": true,
    "hold_reason": "Conflicting authoritative sources"
  }
}
```

The phrase “Conflicting authoritative sources” is the uploaded label, not proof that both claims have equal authority. Reconciliation establishes competence for the specific disputed fact using attributable evidence. A transport system may carry an authentic payer decision; its name alone neither grants nor removes that authority.

The Spine does not prevent upstream systems from publishing `APPROVED`. It prevents promotion of that signal into its verified `current_state` until reconciliation. Both claims remain in provenance. Downstream Spine views must expose the hold and qualification rather than present a held approval as verified readiness.

## 5. Authority enforcement

| Actor | May originate within its domain | Must not rewrite |
|---|---|---|
| PATIENT | Preferences, patient-reported receipt and bounded patient inputs | Clinical orders, payer decisions, pharmacy dispensing facts |
| PRESCRIBER | Prescription clinical data, PA clinical documentation | Pharmacy dispensing state, payer coverage |
| PHARMACY | Dispense events, ready-for-pickup and fulfillment facts | Prescriber orders, PA approval |
| PAYER | Coverage and PA decisions | Prescription details or pharmacy facts |
| SPINE | Coordination metadata, provenance, conflict and verified promotion | Source clinical or coverage data |

Source-domain updates originate at the competent source. This matrix does not authorize the Spine to mutate upstream records or confer unrestricted access on everyone with a matching role.

## 7. Authorized closure completion

The uploaded HTML says `CLOSED` requires completion criteria but does not define them. Its example has `closure_reason` and a generic `timestamp` rather than `closed_at`. The subsequent conversation authorized the following completion under N.B.C. authority.

Promotion to `CLOSED` requires:

1. No active conflict, `HOLD`, or unresolved source reconciliation.
2. No unresolved required next action; `next_required_action = null`.
3. No remaining responsible actor; `responsible_actor = null`.
4. Source-backed required workflow milestones. The PA-required branch uses payer approval; the no-PA branch uses payer-authoritative `PA_NOT_REQUIRED` evidence. Required pharmacy milestones remain attributable.
5. When patient receipt confirmation is required by this episode, an attributable receipt event exists. A patient report retains `confidence = patient-reported`.
6. Required coordination follow-up is completed or explicitly satisfied under the workflow contract.
7. `closure_reason`, `closed_at`, `closure_basis[]`, and provenance references exist.
8. The Spine attests to satisfied coordination predicates without originating the clinical, payer, pharmacy, or patient facts behind them.

The branch-specific milestone clarification prevents the no-PA path from requiring a fictitious PA approval. It is recorded in [specification status](../specification-status.md).

```json
{
  "status": "CLOSED",
  "source": "Spine",
  "responsible_actor": null,
  "next_required_action": null,
  "patient_action": "None",
  "closure_reason": "workflow_complete",
  "closed_at": "2026-10-17T09:00:00-04:00",
  "closure_basis": [
    "payer_approval_verified",
    "pharmacy_dispense_verified",
    "patient_receipt_recorded",
    "follow_up_completed"
  ],
  "provenance_refs": [
    "example_payer_approval_event",
    "example_pharmacy_dispense_event",
    "example_patient_receipt_event",
    "example_follow_up_completion_event"
  ]
}
```

All identifiers in this object are example references. `provenance_refs` is a documentation-level spelling of the authorized provenance-reference requirement; its final type belongs in the Audit & Provenance Contract. `closed_at` is distinct from source-event time and promotion/audit time.

Denial, cancellation, abandonment, expiry, and therapy discontinuation are different outcomes. They cannot be silently represented as successful `CLOSED`. Closure does not mean clinical success.
