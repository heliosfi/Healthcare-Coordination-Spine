v0.1 Audit & Provenance Contract

Immutable event identity, ordering, and evidence retention for PROMOTE, REJECT, and HOLD

On this page
1. Purpose 3. Event Identity 6. Retention 10. Audit Event

1. Purpose

Defines what must be recorded, retained, and made attributable for every consequential operation in the Spine. Ensures provenance is preserved, conflicts are auditable, and no source data is silently overwritten. Operates after State-Transition Contract.

Input
Authorized Events
Process
PROMOTE / REJECT / HOLD
Output
Immutable Audit Trail

2. Core Principles

  • Every event is immutable once accepted
    No updates, only new events
  • Provenance is append-only
    History grows, never shrinks
  • Source authority is preserved
    Original system attribution maintained
  • Rejected and held events are auditable
    DENY and HOLD emit full audit records
  • No silent overwrites
    Conflicts preserve both claims
  • Audit trail enables reconstruction
    Any state at any time is replayable

3. Event Identity

Define immutable Event record. event_id is assigned by Spine on first receipt, source_event_id preserved from origin. Hash chain ensures tamper-evidence.

interface SpineEvent {
  event_id: string;            // UUID v7, assigned by Spine on first receipt
  coordination_id: string;     // Coordination instance
  source_system: string;       // e.g., "epic.prescriber", "surescripts"
  source_event_id: string;     // Preserved from origin, never modified
  source_authority: Authority; // PRESCRIBER | PHARMACY | PAYER | PATIENT
  event_type: EventType;       // PRESCRIBED, DISPENSED, CLAIM_PAID, etc.
  actor_id: string;
  actor_role: string;
  timestamp: string;           // RFC3339 source timestamp
  received_at: string;         // RFC3339 Spine ingest time
  payload_hash: string;        // SHA-256 of canonical content
  previous_event_hash: string | null; // Tamper-evident chain
  content: object;             // Canonical JSON, normalized
}
Immutability: Once event_id is assigned, the entire record is write-once. Corrections arrive as new events with their own source_event_id referencing the original.

4. Ordering

Events may arrive out of order. Ordering determined by: source timestamp, source sequence number if provided, received_at, and causal links via previous_event_hash. Define that current_state is derived from ordered, authorized, promoted events only.

Ordering Precedence
  1. 1
    source.timestampPrimary clinical time
  2. 2
    source.sequence_numberIf provided by origin
  3. 3
    previous_event_hashCausal link
  4. 4
    received_atSpine ingest tiebreaker

current_state is the fold of all ordered, authorized, and promoted events. REJECTED and HELD events never contribute to state.

6. What Must Be Retained

For PROMOTE

  • • event (full immutable record)
  • • authorization decision with authority_basis
  • • transition decision with guard evaluation
  • • promotion record
  • • prior and new state snapshots
  • • responsible_actor change
  • • provenance_refs (full chain)

For REJECT

  • • event (full immutable record)
  • • authorization decision
  • • transition decision with reason_code
  • • attempted from/to state
  • • no state change recorded

For HOLD

  • • event (full immutable record)
  • • authorization decision
  • • transition decision
  • • conflict record if applicable
  • • promotion_blocked flag
  • • unresolved guards
  • • all competing source events

7. Duplicate Detection

Define idempotency key as hash of source_system + source_event_id + coordination_id + event_type. On duplicate, record DUPLICATE_EVENT audit entry, do not create new state.

idempotency_key = SHA256(
  source_system + "|" +
  source_event_id + "|" +
  coordination_id + "|" +
  event_type
)

// On match:
// → emit AuditEvent(action_type=DUPLICATE_EVENT)
// → return existing event_id
// → no new state, no promotion

8. Conflict Evidence

When CONFLICT_DETECTED, retain: all conflicting events with full payloads, authority_basis for each, timestamps, reconciliation inputs, winning_source determination, losing sources preserved, resolution timestamp, resolved_by. Losing claims never deleted.

FieldRetention Requirement
conflicting_events[]Full payloads, not references
authority_basis[]Per-event PRESCRIBER vs PHARMACY rationale
winning_sourceDetermination + timestamp
losing_sources[]Never deleted, marked superseded

9. Closure Evidence

For CLOSED, retain: closure_basis array, all milestone events referenced, follow-up completion evidence, final responsible_actor null, closed_at, closure_reason, full provenance chain from PRESCRIBED to CLOSED.

10. Audit Event Structure

Define AuditEvent. Note every decision including DENY and HOLD must emit audit event.

interface AuditEvent {
  audit_id: string;          // UUID
  timestamp: string;         // RFC3339
  actor: string;             // actor_id
  organization: string;
  patient_ref: string;       // Pseudonymized
  action_type: 'EVENT_RECEIVED' | 'AUTHORIZATION_EVALUATED' |
               'TRANSITION_EVALUATED' | 'STATE_PROMOTED' |
               'STATE_REJECTED' | 'STATE_HELD' |
               'CONFLICT_DETECTED' | 'RECONCILIATION_PERFORMED' | 'CLOSED';
  resource_type: 'SpineEvent' | 'CoordinationState';
  resource_id: string;
  decision: 'ALLOW' | 'DENY' | 'HOLD';
  reason_code: string | null;
  authority_basis: string | null;
  consent_basis: string | null;
  prior_state: string | null;
  resulting_state: string | null;
  provenance_refs: string[]; // event_id, decision_ids
  payload_hash: string;
}

11. Immutability and Retention

Events, decisions, and promotions are immutable. Implement via append-only log with cryptographic hash chaining. Retention period minimum 7 years or per regulatory requirement. No hard delete; revocation recorded as new event.

No Hard Delete
Revocation, correction, or withdrawal must be recorded as a new SpineEvent with event_type='REVOKED' referencing the original via previous_event_hash. Physical deletion violates this contract.

12. Reconstructability

System must be able to reconstruct current_state and any historical state by replaying ordered, promoted events from genesis. Provide function: reconstruct_state(coordination_id, as_of_timestamp).

reconstruct_state("coord_abc123", "2025-12-15T14:30:00Z")
